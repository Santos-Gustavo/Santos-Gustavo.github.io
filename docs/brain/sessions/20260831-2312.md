## A real bug found and fixed along the way

Adding the "Entrar" click broke 26–27 of 44 E2E tests at first — reproducibly, not flaky. Spent significant time ruling out red herrings before finding the real cause:
- Ruled out: orphaned background test processes contaminating results (real, but not *the* cause — see process note below), Supabase auth rate-limiting (checked directly: 5 rapid sequential logins outside the test runner all succeeded in <500ms), accumulated leftover E2E test data (checked directly: 0 leftover projects).
- Actual root cause, confirmed by instrumenting a live run: `page.goto()` waits for the destination's `load` event; `.click()` on a link that triggers navigation does not wait the same way. `#authEmail`/`#authPassword` are plain static HTML, visible immediately, before `js/main.js`'s module script has necessarily run — so a test could click the landing page's "Entrar" link, see the login form, fill it, and click submit *before* `bindAuthEvents()` had registered its click handler. The click did nothing. Confirmed via console timing: the `[ESM boot]` log lines printed *after* the submit click in the failing runs.
- Fix: `await page.waitForLoadState("load");` after every "Entrar" link click, before touching the destination page. Verified: 44/44 passing in 1.8 minutes (faster than the pre-change baseline) on two separate clean runs.

## Process note worth carrying forward

Several `npm run test:e2e` background runs in this session reported "completed" (wrapper exited, notification fired) while the underlying `npm`/`playwright`/Chromium process tree kept running independently — a Windows/git-bash quirk where backgrounded child processes aren't reliably killed when the wrapping shell exits. This caused real test contamination (multiple suites hitting the same port and Supabase test account concurrently) that looked exactly like a code regression until diagnosed. Added a note to the Project State carry line. Future sessions: if a background E2E run's timing looks anomalous, check `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` for orphans before trusting the result.
