# 2026-09-01 11:21 — UX-FIXES-002: account security, client governance, client edit clarity, project client dropdown, progress bar, report navigation safety

## What changed

Eight independent, narrowly-scoped UX/security/quality fixes requested in one batch, on the already-shipped MVP:

1. Confirm-password field on sign-up, validated client-side before any Supabase call.
2. Password reveal/hide toggle on login, sign-up, confirm-password, and the separate password-reset page.
3. Client email governance — must contain exactly one `@`, a domain, and end in `.com`; enforced on create and edit.
4. Client edit form now hides the client list/search/"+ Novo Cliente" while editing, with a dynamic "Editar cliente: [Nome]" heading.
5. Fixed the project-creation client dropdown not reliably showing existing clients.
6. Progress-percentage slider now renders a visible filled track, not just a drag thumb.
7. "Voltar ao Início" repositioned to the report screen's top-right, away from "Gerar Relatório".
8. Added a confirmation dialog before "Voltar ao Início" actually navigates away.

Full detail, root causes, and exact file list: `docs/features/UX-FIXES-002.md`.

## Why

Direct user request — a focused fix batch ahead of contractor validation, explicitly scoped to avoid schema/RLS changes, payment UI, or a broader flow rewrite.

## Notable findings

- **FIX 5's root cause was verified empirically**, not guessed: ran the live app against real Supabase with network/console instrumentation. The datalist query itself was already correct. The actual bug was a fire-and-forget (`.catch()`, not awaited) population call racing a synchronous step-navigation — fixed by awaiting it. A second, historical-only cause (duplicate `companies` rows from before `COMPANY-PROFILE-001`) was investigated and ruled out for the current state, but flagged as a residual risk since it's undetectable without a manual data audit.
- Building FIX 8's confirmation required a new small reusable component (`js/ui/confirm-dialog.js`) since no modal/dialog pattern existed anywhere in the app — confirmed by grep and by `CLIENT-MANAGEMENT-001.md`'s own explicit "no modal exists" precedent note. Kept intentionally generic (title/message/two labeled buttons) so it can be reused for any future confirmation instead of reaching for native `confirm()` again.
- Updating FIX 8 surfaced a real risk to the E2E suite's self-cleaning teardown: `global-teardown.js`'s cleanup retry loop clicks the same "Voltar ao Início" button used everywhere else. Without updating it to also click through the new confirm dialog, every test run's cleanup would have silently stalled. Fixed as part of this batch, verified via a full clean run (39 projects, 55 clients, 1 zero-use company deleted afterward).
